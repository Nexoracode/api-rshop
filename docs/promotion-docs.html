نسخهٔ کامل شامل: انواع پروموشن، انواع شرط‌ها، انواع اکشن‌ها، Variant، Checkout API، Admin API، سناریوهای واقعی، و نکات فرانت‌اند.

۱. معرفی سیستم پروموشن

سیستم Promotion Engine در RSHOP تخفیف‌ها را به‌صورت داینامیک مدیریت می‌کند.

  • کوپن تخفیف درصدی یا مبلغی
  • پیشنهاد شگفت‌انگیز (Flash Deal)
  • ارسال رایگان
  • خرید اول
  • پاداش خرید بعدی
  • پشتیبانی Variant

۲. ساختار کلی یک Promotion

نمونه ساختار کامل
{
  "name": "20% OFF Electronics",
  "type": "coupon",
  "code": "ELEC20",
  "startsAt": "2025-01-01 00:00:00",
  "endsAt": "2025-12-31 23:59:59",
  "conditions": [
    { "type": "category", "categoryIds": [3] },
    { "type": "variant", "variantIds": [101,102] }
  ],
  "actions": [
    { "type": "percent_discount", "value": 20 },
    { "type": "free_shipping" }
  ]
}

۳. انواع PromotionType

پنج نوع اصلی پروموشن در سیستم وجود دارد:

نوع توضیح
coupon دارای code – کاربر باید وارد کند
flash_deal پیشنهاد شگفت‌انگیز – نمایش در صفحه اصلی
free_shipping ارسال رایگان
first_order فقط برای اولین خرید کاربر
next_order_reward صدور کوپن reward برای خرید بعدی

مثال‌های کاربردی:

Coupon — تخفیف درصدی + مبلغی
{
  "name": "Mega Discount",
  "type": "coupon",
  "code": "MEGA50",
  "conditions": [
    { "type": "min_order_amount", "minAmount": 200000 }
  ],
  "actions": [
    { "type": "percent_discount", "value": 10 },
    { "type": "amount_discount", "value": 50000 }
  ]
}
Flash Deal — مخصوص هوم پیج
{
  "type": "flash_deal",
  "name": "TV Flash Deal",
  "conditions": [
    { "type": "category", "categoryIds": [8] }
  ],
  "actions": [
    { "type": "percent_discount", "value": 25 }
  ]
}
Free Shipping – سفارش بالای X تومان
{
  "type": "free_shipping",
  "name": "Free Shipping 400K+",
  "conditions": [
    { "type": "min_order_amount", "minAmount": 400000 }
  ],
  "actions": [
    { "type": "free_shipping" }
  ]
}
First Order — خرید اول + هدیه
{
  "type": "first_order",
  "name": "10% First Order",
  "conditions": [
    { "type": "first_order" }
  ],
  "actions": [
    { "type": "percent_discount", "value": 10 },
    { "type": "amount_discount", "value": 20000 }
  ]
}
Next Order Reward — پاداش خرید بعدی
{
  "type": "next_order_reward",
  "name": "Buy Now Get Coupon",
  "conditions": [
    { "type": "min_order_amount", "minAmount": 300000 }
  ],
  "actions": [
    {
      "type": "next_order_coupon",
      "meta": { "rewardAmount": 50000 }
    }
  ]
}

۴. انواع ConditionType

هر پروموشن می‌تواند چندین شرط داشته باشد. همه شروط باید برقرار باشند تا اکشن‌ها اجرا شوند.

نوع شرط فیلد مورد نیاز توضیح
user userId فقط برای یک کاربر خاص
product productIds اعمال فقط روی محصولات مشخص
category categoryIds اعمال فقط روی دسته‌بندی‌های مشخص
variant variantIds اعمال فقط روی Variantهای مشخص (این همان رنگ/سایز/مدل انتخاب‌شده توسط کاربر است)
min_order_amount minAmount حداقل مبلغ سفارش
first_order - فقط اولین خرید کاربر

مثال‌های جامع Conditions

شرط محصول خاص
{
  "type": "product",
  "productIds": [11, 14, 18]
}
شرط دسته‌بندی خاص
{
  "type": "category",
  "categoryIds": [3, 5]
}
شرط Variant (کاملاً مهم برای فروشگاه)
{
  "type": "variant",
  "variantIds": [101, 102, 205]
}

یعنی این پروموشن فقط روی Variantهایی که ID آنها 101, 102, 205 باشد اعمال می‌شود. حتی اگر همان محصول Variant دیگری داشته باشد → شامل نمی‌شود.

ترکیب Variant + Category
{
  "conditions": [
    { "type": "category", "categoryIds": [4] },
    { "type": "variant", "variantIds": [501, 502] }
  ]
}

فقط محصولاتی که هم در دسته ۴ باشند و هم Variant آنها یکی از 501 یا 502 باشد → شامل می‌شوند.

شرط خرید اول + حداقل مبلغ
{
  "conditions": [
    { "type": "first_order" },
    { "type": "min_order_amount", "minAmount": 300000 }
  ]
}
مثال جامع — ۴ شرط ترکیبی
{
  "conditions": [
    { "type": "variant", "variantIds": [44] },
    { "type": "product", "productIds": [20,30] },
    { "type": "category", "categoryIds": [3] },
    { "type": "min_order_amount", "minAmount": 200000 }
  ]
}

در این نوع، پروموشن فقط زمانی فعال می‌شود که تمام موارد بالا برقرار باشد.

۵. انواع ActionType

بعد از این‌که تمام conditions برقرار شدند، actions روی سفارش اعمال می‌شود.

نوع اکشن پارامتر توضیح
percent_discount value تخفیف درصدی از subtotal
amount_discount value تخفیف مبلغ ثابت (مثلاً 50,000 تومان)
free_shipping - هزینه ارسال = ۰
next_order_coupon meta.rewardAmount پس از سفارش موفق، کوپن برای خرید بعدی صادر می‌شود

مثال‌های کاربردی Actions

تخفیف ترکیبی درصدی + ثابت
{
  "actions": [
    { "type": "percent_discount", "value": 10 },
    { "type": "amount_discount", "value": 20000 }
  ]
}
ارسال رایگان
{
  "actions": [
    { "type": "free_shipping" }
  ]
}
پاداش خرید بعدی (Next Order)
{
  "actions": [
    {
      "type": "next_order_coupon",
      "meta": {
        "rewardAmount": 50000
      }
    }
  ]
}
مثال کامل — سه اکشن همزمان
{
  "actions": [
    { "type": "percent_discount", "value": 7 },
    { "type": "amount_discount", "value": 15000 },
    { "type": "free_shipping" }
  ]
}

۶. بررسی پروموشن — POST /promotions/check

این API قبل از پرداخت فراخوانی می‌شود.
خروجی شامل تخفیف، ارسال رایگان و مبلغ نهایی است.

ساختار ورودی (Request Body)

{
  "userId": 100,
  "code": "OFF20",
  "subtotal": 550000,
  "shippingCost": 30000,
  "isFirstOrder": true,

  "items": [
    {
      "productId": 11,
      "variantId": 44,
      "categoryId": 3,
      "quantity": 1,
      "unitPrice": 550000
    }
  ]
}

پاسخ نمونه (Response Body)

{
  "discount": 110000,
  "freeShipping": true,
  "finalShipping": 0,
  "finalTotal": 440000,
  "appliedPromotionIds": [2, 7]
}
فیلد توضیح
discount مجموع تخفیف نهایی
freeShipping true یعنی ارسال = ۰
finalShipping هزینه ارسال بعد از تخفیف
finalTotal مبلغ پرداخت نهایی کاربر
appliedPromotionIds آیدی پروموشن‌هایی که اعمال شده

خطاهای احتمالی (برای نمایش به کاربر)

{
  "error": "Coupon not applicable to selected products."
}
{
  "error": "Minimum order amount is not satisfied."
}
{
  "error": "Variant ID not eligible for this promotion."
}

۷. APIهای مدیریت پروموشن (Admin Panel)

این بخش برای پیاده‌سازی بخش مدیریت (CMS) طراحی شده و شامل:

  • لیست پروموشن‌ها با فیلترهای کامل
  • ایجاد پروموشن جدید
  • ویرایش
  • حذف
  • فعال / غیرفعال کردن
  • ولیدیشن دقیق برای فرم‌ها
  • مثال‌های واقعی

۷.۱ — دریافت لیست پروموشن‌ها

GET /admin/promotions

Query Params

پارامتر نوع توضیح
page number پیش‌فرض 1
limit number پیش‌فرض 20
type string فیلتر براساس PromotionType
isActive boolean فعال/غیرفعال
search string جستجو در name یا code
startsFrom datetime شروع از تاریخ
endsTo datetime تا تاریخ
hasCode boolean پروموشن‌هایی با code

مثال درخواست


GET /admin/promotions?page=1&limit=10&type=coupon&isActive=true&search=20

پاسخ نمونه

      "endsAt": "2025-12-31 23:59:59",

۷.۲ — ایجاد پروموشن جدید

POST /admin/promotions

ساختار کامل Request Body شامل همه حالات ممکن:

{
  "name": "Special Var 101 Deal",
  "type": "coupon",
  "code": "VAR101",

  "startsAt": "2025-03-01 00:00:00",
  "endsAt": "2025-03-30 23:59:59",
  "usageLimit": 100,
  "isActive": true,

  "conditions": [
    { "type": "variant", "variantIds": [101,102] },
    { "type": "min_order_amount", "minAmount": 300000 },
    { "type": "user", "userId": 55 }
  ],

  "actions": [
    { "type": "percent_discount", "value": 15 },
    { "type": "free_shipping" }
  ]
}

نکات بسیار مهم برای فرانت‌اند (Create)

  • اگر نوع = coupon → فیلد code اجباری
  • اگر نوع ≠ coupon → فیلد code باید null یا خالی ارسال شود
  • اگر نوع = next_order_reward → فیلد meta.rewardAmount اجباری
  • شرط‌ها باید آرایه باشند (حتی در یک شرط)
  • اکشن‌ها نیز باید آرایه باشند
  • variantIds → فقط آرایه از عدد

۷.۴ — ویرایش پروموشن

PUT /admin/promotions/:id

مثال:

{
  "name": "20% Updated",
  "conditions": [
    { "type": "variant", "variantIds": [101] }
  ],
  "isActive": false
}

نکتهٔ مهم: در ویرایش، conditions یک آرایه کامل است. اگر یک شرط را حذف کنی → باید کل conditions را دوباره ارسال کنی.

۷.۶ — فعال/غیرفعال کردن

PATCH /admin/promotions/:id/toggle 
{ "isActive": false }

۷.۷ — دریافت فقط پروموشن‌های فعال

GET /admin/promotions/active 
[
  { "id": 3, "name": "Flash Deal TVs 20%" },
  { "id": 5, "name": "Free Shipping 300K+" }
]

۷.۸ — خطاهای ولیدیشن (برای نمایش در UI)

خطا توضیح راه‌حل
code already exists کد تخفیف تکراری کد جدید انتخاب کنید
invalid type نوع پروموشن اشتباه فقط از enum تعریف‌شده استفاده کنید
conditions invalid ساختار شرط‌ها اشتباه است مثلاً variantIds باید آرایه باشد
actions empty هیچ اکشنی تعریف نشده حداقل یک action لازم است
start > end تاریخ شروع بزرگ‌تر از تاریخ پایان اصلاح تاریخ‌ها

۸. Promotion Engine — منطق اعمال پروموشن

PromotionEngine مسئول اعمال اکشن‌هاست، اما قبل از آن PromotionValidatorService باید شرایط را تایید کند.

منطق کلی Engine

  1. گرفتن لیست پروموشن‌های فعال
  2. فیلتر براساس تاریخ (startsAt ≤ now ≤ endsAt)
  3. فیلتر براساس code (در صورت وجود)
  4. اعتبارسنجی همهٔ conditions
  5. اعمال اکشن‌ها (percent/amount/free shipping/...)
  6. بازگرداندن نتیجه

کد واقعی اعتبارسنجی Variant در Validator


// PromotionValidatorService.ts

if (cond.type === ConditionType.VARIANT) {
  const required = cond.variantIds ?? [];  // آیدی‌های لازم
  const basketVariants = order.items.map(i => i.variantId);

  const match = required.some(v => basketVariants.includes(v));

  if (!match) return false;
}

کد واقعی اعمال اکشن‌ها


// PromotionEngineService.ts

switch (action.type) {

  case ActionType.PERCENT_DISCOUNT:
    discount += (order.subtotal * action.value) / 100;
    break;

  case ActionType.AMOUNT_DISCOUNT:
    discount += action.value;
    break;

  case ActionType.FREE_SHIPPING:
    freeShipping = true;
    break;

  case ActionType.NEXT_ORDER_COUPON:
    // فقط ثبت می‌کنیم که اعمال شد
    break;
}

۹. نکات خیلی مهم برای فرانت‌اند

  • همیشه قبل از پرداخت POST /promotions/check را صدا بزنید.
  • اگر کاربر کد تخفیف وارد کرد → فقط همان پروموشن بررسی می‌شود.
  • اگر code وارد نشده → همهٔ پروموشن‌های بدون code بررسی می‌شوند.
  • برای محصولات دارای variant:
    variantId الزامی است
  • اگر variantId اشتباه ارسال شود → هیچ پروموشنی اعمال نمی‌شود.
  • بررسی کنید که مبلغ تخفیف از subtotal بیشتر نشود.
  • freeShipping اگر true باشد → هزینهٔ ارسال = ۰
  • اگر پروموشن type=first_order باشد:
    isFirstOrder = true باید ارسال شود.
  • بعد از سفارش موفق → اگر promo شامل next_order_reward باشد سمت بک‌اند کوپن reward ساخته می‌شود.
